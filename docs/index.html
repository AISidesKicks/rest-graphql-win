The same question, two ways

"How much revenue is at risk from accounts with an overdue invoice and open critical tickets?" REST needs a small chain of calls, GraphQL needs one. Below the panels, press the button: if the lab is running on 127.0.0.1:8000 you get the live answer, otherwise the recorded output from the seeded dataset.

REST 3 to 4 round trips

# 1. accounts that owe money
curl 'http://127.0.0.1:8000/api/accounts?status=past_due&limit=50'

# 2. their invoices
curl 'http://127.0.0.1:8000/api/invoices?status=overdue&limit=50'

# 3. their tickets, one account at a time
curl 'http://127.0.0.1:8000/api/tickets?account_id=42&status=open'

# 4. the plan behind the account
curl 'http://127.0.0.1:8000/api/accounts/42'

GraphQL 1 round trip

query RevenueAtRisk {
  accounts(status: PAST_DUE, limit: 50) {
    items {
      id
      name
      invoices(status: OVERDUE) { totalCents dueAt }
      tickets(status: OPEN, priority: CRITICAL) {
        id subject priority
      }
    }
  }
}

REST: one HTTP call per resource, the client stitches the graph together.
  - round trips add up, and the N+1 trap waits for every account
  - caches work per URL, which is simple and predictable
  - errors are HTTP status codes, so the client branch is explicit

GraphQL: one HTTP call, the server resolves the graph.
  - the client asks for exactly the fields it needs, no over fetching
  - a DataLoader style batch loader keeps the N+1 trap out
  - errors arrive inside the payload, so HTTP 200 does not mean success

The three panels

The sketches that started the project. Each one becomes a chapter with runnable commands, numbers and traces.

Run the lab yourself

One pixi environment, one ASGI app, one port. The chapters are markdown files in the repo, every command is copy and paste ready.

1. Seed and build the star schema

pixi run seed # small preset, deterministic pixi run etl # SQLite to DuckDB pixi run seed -- --scale large

2. Serve REST, GraphQL and MCP

pixi run serve # http://127.0.0.1:8000 pixi run serve -- --tls # https://127.0.0.1:8443, mkcert # GraphiQL lives at /graphql

3. Measure the differences

pixi run bench # calls, round trips, ms, bytes pixi run tools # MCP catalog and token cost pixi run savings # native MCP versus CodeMode

The stack

  • FastAPI for the REST side and the OpenAPI document
  • Strawberry for the GraphQL schema and GraphiQL
  • SQLite as the operational database, WAL mode
  • DuckDB as the analytical database, columnar
  • MCP Python SDK serving Streamable HTTP at /mcp
  • Pydantic Monty as the CodeMode sandbox
  • tiktoken to count what the model actually pays
  • OpenTelemetry with a JSONL exporter and OTLP
  • pixi holding the whole environment
  • pytest and a verify script for the whole stack
